# 微信云托管部署手册

> 给要把本项目部署到**微信云托管**的人看。按顺序照着做即可，每一步都写了「为什么」和「错了会怎样」。
>
> 目标：**手机上的真机小程序能正常用上服务**，而不是只在电脑模拟器里跑。

---

## 零、先搞清楚这套东西长什么样

```
                    ┌─────────────────────────────────────────┐
   微信 App          │           微信云托管（上海地域）          │
   （真机）          │                                         │
      │             │  ┌──────────────┐   ┌───────────────┐  │
      │ callContainer│  │   nqx 服务    │──▶│  MySQL 8.0    │  │
      │ （内网、免域名）│  │  (容器:8080)  │   │ （云托管自带） │  │
      └────────────▶│  │              │   └───────────────┘  │
                    │  │  同时托管      │   ┌───────────────┐  │
   浏览器（管理后台） │  │  管理后台静态页 │──▶│  Redis        │  │
      │             │  └──────┬───────┘   │ （自己买，VPC）│  │
      │  公网域名     │         │           └───────────────┘  │
      └────────────▶│         ▼                               │
                    │  ┌───────────────┐                      │
                    │  │ 腾讯云 COS     │  ← 图片文件           │
                    │  │ （你自己已有）  │                      │
                    │  └───────────────┘                      │
                    └─────────────────────────────────────────┘
```

**四个关键事实**（记不住就回来查）：

| 事实 | 后果 |
|---|---|
| 云托管**只**提供容器 + MySQL | Redis 要自己买 |
| 云托管**只有「上海」地域** | Redis 必须买上海，**跨地域永远连不上** |
| 容器磁盘是**临时的** | 图片必须放 COS，不能存本地 |
| 小程序走 `callContainer` **不需要配服务器域名** | 但必须改代码才会走它（见 §7） |

## 二、阶段一：本地先把镜像跑通（强烈建议）

**为什么先在本地做**：云托管的在线构建很慢（要拉 Maven 依赖），
在那边反复改、反复等，一次十几分钟。本地先验证 Dockerfile 没问题，能省掉大量往返。

### 2.1 启动 Docker Desktop

```powershell
docker version
```
看到 `Server: Docker Engine` 才算 Docker 起来了（只有 Client 不行）。

### 2.2 构建镜像

```powershell
cd E:\springboot\纽启新生
docker build -t nqx-backend:1.0.0 .
```

首次构建要下载 Maven 依赖，**10~20 分钟**，之后有层缓存会快很多。

### 2.3 用 compose 起一套完整环境验证

```powershell
copy .env.example .env
# 编辑 .env：填 MySQL/Redis 密码、微信凭证、COS 参数
docker compose -p nqx up -d
docker compose -p nqx logs -f app
```

> ⚠️ **必须加 `-p nqx`**。本项目目录名是中文（`纽启新生`），
> Docker Compose 从目录名推导项目名会失败，报 `project name must not be empty`。

看到这行就算成功：
```
Started NqxApplication in xx seconds
文件存储：腾讯云 COS 模式 | bucket=xxx | region=ap-shanghai
```

### 2.4 验证上传真的进了 COS

```powershell
# 登录拿 token
$r = Invoke-RestMethod -Uri "http://127.0.0.1:8080/admin/auth/login" -Method Post `
     -ContentType "application/json" -Body '{"username":"admin","password":"Admin@123"}'
$token = $r.data.token

# 上传一张图
curl.exe -s -X POST -F "file=@uploads\product\1.png" `
  -H "Authorization: Bearer $token" `
  "http://127.0.0.1:8080/admin/file/upload?bizType=product"
```

**期望**：返回的 `data` 是 `https://<你的桶>.cos.ap-shanghai.myqcloud.com/uploads/product/...`
（而不是 `/files/product/...`）

- 返回 `/files/...` → 说明 `UPLOAD_TYPE` 还是 `local`，检查 `.env`
- 启动就失败并提示「缺少必填配置」→ COS 三个变量没配齐

## 三、阶段二：开通云托管环境 + MySQL

### 3.1 创建环境

1. 打开 [微信云托管控制台](https://cloud.weixin.qq.com/cloudrun)
2. 选择你的小程序（AppID `wxec4d8d60fdbb9c24`）
3. 创建环境：**地域选「上海」**（和后面买的 Redis 必须一致）

### 3.2 开通 MySQL

控制台 → MySQL → 按提示输入密码开通。

**开通时要注意的三件事**：

| 项 | 怎么选 | 为什么 |
|---|---|---|
| 版本 | **8.0** | 我们用了 8.0 特性；开通后**不能改版本** |
| 大小写敏感 | 建议选**不敏感** | 开通后**不能改**；选了敏感后表名大小写必须严格一致 |
| 自动暂停 | **关闭** | 见下方说明 |

> **为什么要关自动暂停**：MySQL 默认 10 分钟无请求就暂停，下次请求冷启动期间会返回
> `CynosDB serverless instance is resuming, please try connecting again.`
> 表现是「第一次打开系统报错，刷新一下又好了」，非常迷惑。
> 关掉后一直按最小算力（0.25 CCU）计费，量很小。

### 3.3 记下 MySQL 的内网地址

MySQL 页面能看到**内网地址**和端口（3306）。后面配环境变量要用。

> 不需要开外网地址。本地连库可以用「数据库管理」跳转 DMC。

## 四、阶段三：Redis + VPC（最容易卡住的一步）

### 4.1 先把概念讲明白

云托管**不提供 Redis**，要自己买腾讯云「云数据库 Redis」。

买完之后，容器和 Redis 要能通信，有两条路：

| 方式 | 类比 | 结果 |
|---|---|---|
| 公网 | 两台机器各自拨号，互相打手机 | ❌ 慢、按流量收费、暴露在互联网 |
| **内网 / VPC** | 两台机器在同一个办公室，直接喊话 | ✅ 快、免费、外人进不来 |

**VPC（私有网络）** = 腾讯云给你划的一个「虚拟机房」。
同一个机房里的机器可以用**内网 IP** 互相访问。

> 把 VPC 想成**小区**、子网想成**楼栋**。
> 同小区不同楼栋之间是可以走过去的（官方原话：「同一 VPC 内子网间默认是互通的」）。
> **所以只要 VPC 一致就行，子网不必相同。**

### 4.2 买 Redis（五步）

**第 1 步：用「云托管绑定」的腾讯云账号登录**

买 Redis 必须用同一个腾讯云账号，否则 VPC 不通。

登录方式（二选一）：
- 腾讯云控制台 → 登录 → 选「小程序公众号」→ 微信扫码选择本小程序
- 云托管控制台 → 费用中心 → 充值与账单 → 获取腾讯云账号登录态

**第 2 步：买实例**

腾讯云 → 云数据库 Redis → 新建：

| 项 | 选什么 |
|---|---|
| 地域 | **上海** ⚠️ |
| 网络 / VPC | 记下 VPC ID（可以新建） |
| 规格 | 最小档够用（会话 + 缓存 + 延迟队列，数据量很小） |
| 密码 | 设一个强密码，记下来 |

买完在实例详情里记下 **内网 IP**、**端口**（通常 6379）、**VPC ID**。

**第 3 步：把云托管服务接进这个 VPC（关键）**

微信云托管控制台 → 你的服务 → **设置 → 私有网络设置** → 启用 → 填上一步的 **VPC ID**。

> 这一步做完，容器才「搬进」Redis 所在的小区。
> 没做这一步，无论怎么配 IP 都连不上。

**第 4 步：配安全组**

腾讯云 Redis → 安全组 → 允许云托管服务所在网段**入站 6379**。

**第 5 步：配环境变量**（部署时一起填，见 §6）

```
REDIS_HOST=<Redis 内网 IP>     ← 一定用内网 IP，不是公网地址
REDIS_PORT=6379
REDIS_PASSWORD=<你设的密码>
REDIS_DATABASE=0
```

### 4.3 连不上时的排查顺序（官方清单，按命中率排）

**① 先在 webshell 里测网络**（最直接，能立刻分清是「网络不通」还是「配置错了」）

云托管 → 部署发布 → 点「实例个数」→ 进入 pod：

```bash
nc <redis内网IP> 6379
auth <密码>
info
```

- `nc` 就报错 → 网络问题，往下看
- `nc` 能进但 `auth` 失败 → 密码错
- 全都正常 → 是应用配置问题（检查 `REDIS_HOST` 是不是填成了公网 IP）

> 容器里可能没有 `nc`：`apt-get update && apt-get install -y netcat-openbsd`。

**② 检查资源互联授权状态**

云托管 → 设置 → 环境设置 → 资源互联，看**授权状态是否正常**。

**③ 检查 VPC 是否真的一致**

云托管 → 服务 → 设置 → 私有网络设置，填的 VPC ID 要和 Redis 实例的 VPC ID **完全相同**。

**④ 检查地域**

云托管只有**上海**。买了成都/广州的 Redis → 永远连不上，且**地域不能改**，只能重买。

**⑤ 检查安全组**是否挡了入站。

## 五、阶段四：COS 子账号（别用主账号密钥）

**为什么**：主账号密钥一旦泄露，整个腾讯云账号（含数据库、其它项目）都危险。
子账号密钥泄露，损失被限制在「一个桶的一个目录」。

### 5.1 创建子账号

1. 腾讯云 → **访问管理 CAM** → 用户 → 新建用户 → **编程访问**
2. 记下 SecretId / SecretKey（**只显示一次**）
3. 关联策略：新建自定义策略，只授权目标桶的 `uploads/*`：

```json
{
  "version": "2.0",
  "statement": [
    {
      "effect": "allow",
      "action": ["cos:PutObject", "cos:GetObject", "cos:HeadObject"],
      "resource": [
        "qcs::cos:ap-shanghai:uid/<你的APPID>:<桶名>/uploads/*"
      ]
    }
  ]
}
```

> `<桶名>` 要写完整形式（含 APPID 后缀），例如 `nqx-1300000000`。

### 5.2 桶的地域问题

你现有的桶如果不在**上海**（比如在成都），有两条路：

| 方案 | 说明 |
|---|---|
| **继续用现有桶**（跨地域） | 图片**读取**走 CDN 没影响；**上传**走公网，产生少量流量费。最简单 |
| 在上海新建一个桶 | 上传走内网免费；但要重新配策略和域名 |

> 跨地域不影响功能，只影响上传成本（几 MB/月级别，可忽略）。**建议先用现有桶跑通**。

## 六、阶段五：部署服务

### 6.1 上传代码 / 推镜像

两种方式，**推荐第二种**：

| 方式 | 说明 |
|---|---|
| 控制台上传代码，云端构建 | 简单，但每次构建十几分钟（要拉 Maven 依赖） |
| **本地 build 后推镜像仓库** | 快，且能先在本地验证镜像没问题 |

推镜像流程（控制台 → 服务 → 镜像仓库里能看到推送命令）：

```powershell
docker login ccr.ccs.tencentyun.com --username=<你的>
docker tag nqx-backend:1.0.0 <镜像仓库地址>/nqx:<版本号>
docker push <镜像仓库地址>/nqx:<版本号>
```

### 6.2 服务设置

| 项 | 值 |
|---|---|
| 端口 | **8080** |
| 健康检查 | `/actuator/health` |
| 实例数 | **1**（首部署必须 1） |

> **为什么首部署必须 1 个实例**：应用启动时 Flyway 会跑数据库迁移。
> 多实例同时启动会并发迁移，可能报错。表建好之后再加实例。

### 6.3 环境变量（照着填）

```
# ---- 必填 ----
SPRING_PROFILES_ACTIVE=prod
DB_HOST=<MySQL 内网地址>
DB_PORT=3306
DB_NAME=nqx
DB_USERNAME=root
DB_PASSWORD=<MySQL 密码>
DB_USE_SSL=false                       ← 云托管 MySQL 走内网，不需要 TLS
REDIS_HOST=<Redis 内网 IP>
REDIS_PASSWORD=<Redis 密码>
WX_APP_ID=wxec4d8d60fdbb9c24
WX_APP_SECRET=<你的>
COS_SECRET_ID=<子账号 SecretId>
COS_SECRET_KEY=<子账号 SecretKey>
COS_REGION=ap-shanghai
COS_BUCKET=<桶名，含 APPID 后缀>
INIT_ADMIN_PASSWORD=<换掉默认的 Admin@123！>

# ---- 选填 ----
COS_KEY_PREFIX=uploads
COS_DOMAIN=                            ← 绑了 CDN 才填
SPRINGDOC_ENABLED=false                ← 正式环境必须关
REDIS_DATABASE=0
```

> **`DB_USE_SSL=false` 是必要的**：`application-prod.yml` 默认 `useSSL=true`，
> 而云托管 MySQL 的内网连接不提供 TLS，不关会连不上。

### 6.4 开启公网访问 ⚠️

控制台 → 服务 → 公网访问 → **打开**。

**这一步不能省**：管理后台是人用浏览器打开的，纯内网只有小程序能调。
关了公网，你自己都进不去后台。

（小程序走 `callContainer` 仍然走内网，不受公网开关影响。）

### 6.5 首次启动验证

看部署日志，应该出现：

```
Started NqxApplication in xx seconds
文件存储：腾讯云 COS 模式 | bucket=xxx | region=ap-shanghai
```

然后浏览器打开 `https://<公网域名>/actuator/health`，看到 `{"status":"UP"}` 即通。

## 七、阶段六：管理后台（前端）

**已经把前端打进同一个镜像了，这一步不需要你额外操作。**

### 7.1 是怎么做的

`Dockerfile` 里多了一个 `ui-builder` 阶段：

```
node:20-alpine  →  npm ci  →  npm run build  →  /ui/dist
                                                   │
                                                   ▼
                              COPY 到运行镜像的 /app/static
                                                   │
                                                   ▼
        Spring 通过 spring.web.resources.static-locations=file:/app/static/ 提供
        SpaFallbackFilter 把 /order/recycle 这类前端路由回退到 index.html
```

**为什么不用「云托管 → 静态资源存储」一键部署**：静态资源是纯 CDN，
它**不会**把 `/admin/auth/login` 转发给后端容器。前端只能直连后端域名 →
跨域 + 配 CORS；而 `history` 路由模式下刷新深链还会 404。

打进同一个镜像就都解决了：**同源、无跨域、一个域名一个端口**。

### 7.2 两个关键实现点（改代码时要知道）

**① `dist` 必须在镜像里，不能靠本地 `dist`**

`.dockerignore` 里排除了 `nqx-ui/dist/`（本地构建产物不该进上下文），
镜像里的 dist 是 `ui-builder` 阶段现构建的。所以本地的 `dist` 是不是最新，**不影响镜像**。

顺带的好处：`npm run build` 里包含 `vue-tsc --noEmit`（类型检查），
**类型错误会让镜像构建失败** —— 宁可构建失败，也不要打出一个"能启动但页面报错"的镜像。

**② SPA 回退只回退"页面请求"，绝不回退 API**

Vue 用的是 history 模式，`/order/recycle` 这种地址在服务器上没有对应文件，
刷新会 404，所以必须回退到 `index.html`。

但回退规则必须是**白名单式**的（`SpaFallbackFilter`）：

| 请求 | 处理 |
|---|---|
| `GET /order/recycle` | ✅ 回退到 index.html |
| `GET /assets/index-abc123.js` | ✅ 正常返回（有扩展名，不回退） |
| `GET /admin/no-such-api` | ✅ **返回 JSON 错误，不回退** |
| `GET /actuator/health` | ✅ 正常返回 JSON |
| `POST /admin/auth/login` | ✅ 正常返回（只处理 GET） |

> **为什么要这么小心**：如果给 `/**` 注册通配资源处理器做回退，
> 会把 API 的 404 也变成 index.html —— 前端拿到的是一段 HTML 而不是
> `{"code":404}`，排查时会完全失去方向。这个项目已经因为"404 被伪装"
> 吃过一次亏（见 docs/06 第 39 条）。

### 7.3 本地想验证 SPA 模式

生产镜像里是自动的。本地想试可以这样启动：

```powershell
java -jar nqx-web/target/nqx.jar --spring.profiles.active=dev `
  --nqx.web.spa-enabled=true `
  --spring.web.resources.static-locations=file:E:/你的路径/nqx-ui/dist/
```

然后访问 `http://127.0.0.1:8080/` 和 `http://127.0.0.1:8080/order/recycle`，都应该出页面；
而 `http://127.0.0.1:8080/admin/xxx` 应该返回 JSON 而不是 HTML。

## 八、阶段七：小程序

**代码已经改好了，你只需要改一个常量。**

### 8.1 已经实现的东西

`utils/request.js` 里抽了一层 `transport()`：

```
页面 → wx.cloud.callContainer（被垫片接住）
         │
         ├─ 业务逻辑：路径映射 / token / 解包 / 401 静默重登
         │
         └─ transport() 决定用哪种传输
              ├─ LOCAL/LAN/PROD  →  wx.request（直连 HTTP 地址）
              └─ CLOUDRUN        →  原生 wx.cloud.callContainer（走内网）
```

`app.js` 里也按需加了 `wx.cloud.init()`：

```js
if (env.USE_CALL_CONTAINER) {
  wx.cloud.init({ env: env.CLOUDRUN_ENV_ID, traceUser: true });
}
```

### 8.2 你要做的：改两行常量

打开 [`nqx-miniprogram/utils/env.js`](../../nqx-miniprogram/utils/env.js)：

```js
// 1) 换成你自己的云托管环境 ID
const CLOUDRUN_ENV_ID = 'your-cloudrun-env-id';

// 2) 换成你的服务名（云托管控制台 → 服务管理 → 服务列表）
const CLOUDRUN_SERVICE = 'app';

// 3) 关键：把 ENV 从 'LOCAL' 改成 'CLOUDRUN'
const ENV = 'CLOUDRUN';
```

> ⚠️ **环境 ID 与服务名必须和云托管控制台里的一致**，否则 `callContainer`
> 会报「环境不存在」或「服务不存在」。

### 8.3 还有一件事：基础库版本

小程序后台 → 设置 → 基本设置 → **基础库最低版本设为 2.23.0 及以上**
（`wx.cloud.callContainer` 的要求）。低于这个版本在部分机型上会直接报不支持。

### 8.4 切到 CLOUDRUN 之后你会得到什么

| 好处 | 说明 |
|---|---|
| ✅ **不用配服务器域名** | callContainer 走内网，不经过公网域名校验 |
| ✅ 不用 HTTPS / 备案 | 同上 |
| ✅ **真机能直接用** | 这是部署最大的收益 —— 直连模式下真机几乎没法测 |
| ✅ 后端能直接从请求头拿 openid | 可以彻底不调 `jscode2session`（可选优化，暂未做） |

### 8.5 注意：图片上传不走 callContainer

`wx.uploadFile` 是独立 API，不能走 callContainer，仍然打 `API_BASE_URL`。
所以切到 CLOUDRUN 之后：

- **接口**请求走内网 ✅
- **图片上传**仍走公网域名（因为要发 multipart 大文件）

这意味着**你仍然需要给上传接口配一个可访问的 HTTPS 地址**。
两个办法：

1. 把云托管的**公网域名**配进「服务器域名」（云托管默认域名通常已备案，可直接用）；
2. 或者改成"后端发预签名 URL，小程序直传 COS"（更彻底，但目前没实现）。

> 我们的 `utils/upload.js` 会在上传前把超过 300KB 的图压到 quality 72，
> 大幅降低被网关拒掉的概率。

## 十一、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 启动失败：`缺少必填配置： COS_SECRET_ID...` | COS 变量没配齐 | 补齐环境变量，或临时 `UPLOAD_TYPE=local` |
| 启动失败：`Communications link failure` | MySQL 地址错/没开内网 | 核对内网地址；`DB_USE_SSL=false` |
| 启动失败：`CynosDB serverless instance is resuming` | MySQL 自动暂停冷启动 | 控制台关掉自动暂停，或重启服务重试 |
| `Unable to connect to Redis` | VPC 没配 / 地域不对 / 安全组 | 按 §4.3 五步排查 |
| 第一次打开系统报错，刷新就好 | MySQL 冷启动 | 同上，关自动暂停 |
| 图片全部裂图 | `UPLOAD_TYPE` 还是 local | 改成 cos 并配齐参数 |
| 图片返回 `/files/...` | 同上 | 同上 |
| 后台能开但接口 404 | 前端没走 nginx 反代 | 按 §7 方案 A 改 Dockerfile |
| 小程序真机连不上 | 还在走 `wx.request` | 改垫片（§8.2），或配服务器域名 |
| `docker compose` 报 `project name must not be empty` | 目录名是中文 | 加 `-p nqx` |

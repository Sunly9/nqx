# 部署运维手册

> 给**开发者 / 运维**看：怎么把系统跑起来、怎么配置、怎么备份、出故障怎么查。
> 普通用户请回到 [手册索引](README.md)。

---

## 一、先选一种运行方式

同一个项目有三种跑法，**选一种即可，不要混着跑**（原因见 §7.1）。

| 方式 | 用在哪 | 需要什么 | 难度 |
|---|---|---|---|
| **A. 本地开发** | 自己电脑上调代码 | JDK 17 + Maven + 本机 MySQL + 本机 Redis | ⭐ |
| **B. Docker 本地** | 想验证"打包成镜像能不能跑" | Docker Desktop | ⭐⭐ |
| **C. 微信云托管** | **正式上线给小程序用** | 微信小程序账号 + 云托管 | ⭐⭐⭐ |

> **A 和 B 用的是两份不同的数据库。** 见 §7.1。

---

## 二、环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **17**（不是 18/21） | 项目在 17 上验证过；21 未测 |
| Maven | 3.9.x | 需要能离线构建（`-o`） |
| MySQL | 8.0.x | 需要 `utf8mb4` |
| Redis | 5.0+ | 只用基础命令，老版本也能跑 |
| Node.js | 18+ | 只给管理后台前端用 |
| Docker | 24+（可选） | 方式 B / C 用 |

**为什么 JDK 锁 17**：Spring Boot 3.5 要求 17+，而 18 是非 LTS（已停止维护）。选 17 是为了避开"上线后 JDK 先过期"的事。

## 三、方式 A：本地开发运行

### 一条命令启动

```powershell
.\scripts\start-local.ps1
```

这个脚本会依次做：检查 JDK → 检查 MySQL/Redis 是否在跑 → 杀掉占用 8080 的旧进程 → `mvn package` → 启动 → 打印访问地址。

### 手动启动（脚本失效时）

```powershell
# 1. 构建
$env:JAVA_HOME='E:\springboot\tools\jdk-17'
& 'E:\springboot\tools\apache-maven-3.9.16\bin\mvn.cmd' -B -ntp -o -f pom.xml package -DskipTests

# 2. 启动（dev 配置）
& "$env:JAVA_HOME\bin\java.exe" -Dfile.encoding=UTF-8 `
    -jar nqx-web\target\nqx.jar --spring.profiles.active=dev
```

### 访问地址

| 入口 | 地址 |
|---|---|
| 后端健康检查 | http://127.0.0.1:8080/actuator/health （应返回 `{"status":"UP"}`） |
| 接口文档 | http://127.0.0.1:8080/swagger-ui.html |
| 管理后台（开发） | `cd nqx-ui; npm run dev` → http://127.0.0.1:5173 |
| 小程序 | 微信开发者工具打开 `nqx-miniprogram` |

### dev 配置的关键行为

- **微信登录是模拟的**：`nqx.wechat.mock-enabled=true`，不需要真实 AppID。传 `code: "dev:张三"` 就能以任意身份登录
- **接口文档默认开启**
- **会打印 SQL**（便于排查）

## 四、方式 B：Docker 本地运行

### 起三个容器

```powershell
Copy-Item .env.example .env
notepad .env          # 按 §6 改端口和密码
docker compose up -d --build
docker compose ps     # 三个都要是 healthy
```

### ⚠️ 必须先改端口

`docker-compose.yml` 默认把 MySQL 映射到宿主机 3306、Redis 映射到 6379。**如果本机已经装了 MySQL/Redis，这两个端口会被占，容器起不来。**

改 `.env`：

```properties
MYSQL_PORT=13306      # 不要用 3306
REDIS_PORT=13379      # 不要用 6379
APP_PORT=8080
SPRING_PROFILES_ACTIVE=dev
```

**容器内部端口不用改** —— compose 里写的 `${MYSQL_PORT:-3306}:3306`，冒号左边是宿主机、右边是容器内。

### 常用命令

```powershell
docker compose ps                   # 状态
docker compose logs -f app          # 跟踪应用日志
docker compose restart app          # 只重启应用
docker compose up -d --build app    # 改了代码只重建应用
docker compose down                 # 停止并删容器（数据卷保留）
docker compose down -v              # ⚠️ 连数据卷一起删 = 数据库清空
docker ps --filter "name=nqx"       # 只看本项目的容器
```

> **`docker compose ps` 只显示当前目录 compose 文件定义的容器**，所以有别的项目在跑也不会干扰。

## 五、方式 C：微信云托管（正式上线）

### 5.1 为什么选云托管

| | 云托管 | 自建服务器 |
|---|---|---|
| 域名备案 | **不需要** | 必须（1~3 周） |
| HTTPS 证书 | 自动 | 自己申请配置 |
| 反向代理 / Nginx | **不需要** | 需要 |
| MySQL / Redis | 平台托管 | 自己装 |
| 小程序接入 | `wx.cloud.callContainer` 走微信内网 | 要配「request 合法域名」 |

**对小程序的场景，云托管省掉的麻烦最多 —— 尤其是不用备案。**

### 5.2 需要哪些文件

| 文件 | 云托管要不要 | 说明 |
|---|---|---|
| `Dockerfile` | ✅ **要** | 云托管只接受容器 |
| `docker-compose.yml` | ❌ **不用** | 它是"一次起三个容器"给本地/自建服务器用的 |

因为云托管里 **MySQL 和 Redis 用平台托管的**，你只上传**一个**容器（后端）。

### 5.3 部署步骤

1. **确认小程序已认证**（`mp.weixin.qq.com`）
2. **开通云托管**（`cloud.weixin.qq.com`），新建环境
3. **建 MySQL / Redis 托管实例**，记下连接地址、端口、账号、密码
4. **新建服务，服务名必须是 `app`**
   - 小程序页面里的 `service: 'app'` 是写死的，名字不对就连不上
   - 部署方式选 Git 仓库（能自动构建）或上传代码包
5. **配环境变量**（见 §6）
6. **部署**，等状态变成运行中
7. **小程序端切到云托管**（见 §5.4）

### 5.4 小程序端怎么切

小程序里**所有页面都在用 `wx.cloud.callContainer`**，中间隔着一个"垫片"（`utils/request.js`）。

```
现在（本地）：  页面 → callContainer → 【垫片】→ wx.request → 127.0.0.1:8080
云托管：       页面 → callContainer → 【垫片】→ 真正的云托管通道 → 你的容器
```

**所以只需要改垫片这一个文件，24 个页面一行都不用动。**

需要改三处：

| 文件 | 改什么 |
|---|---|
| `utils/request.js` | 垫片的目标从 `wx.request` 改成真正的 `wx.cloud.callContainer` |
| `utils/env.js` | `ENV` 改成 `'CLOUD'`，或加一个分支 |
| `app.js` | 恢复 `wx.cloud.init({ env: '你的云托管环境ID' })` |

> ⚠️ **字段位置要注意**：页面里现在写的是 `env: 'xxx', service: 'app'`（顶层字段），而云托管官方 API 是 `config: { env }` + `header: { 'X-WX-SERVICE': 'app' }`。**对接时以[云托管最新文档](https://developers.weixin.qq.com/miniprogram/dev/wxcloudrun/src/development/call/)为准**，在垫片里做一次字段转换即可。

**项目里记录的历史信息**（供参考）：
- 小程序 AppID：`wxec4d8d60fdbb9c24`
- 旧云托管环境 ID：`your-cloudrun-env-id`
- 服务名：`app`

### 5.5 前端（管理后台）怎么部署

管理后台是 Vue3 静态文件，有两种放法：

1. **云托管静态网站托管** —— 把 `npm run build` 出来的 `dist/` 传上去
2. **再建一个容器** —— 用 Nginx 镜像托管 `dist/`

⚠️ 注意 `.dockerignore` 里**故意排除了 `nqx-ui/` 和 `dist/`**，所以后端镜像里没有前端。这是对的：前端应该单独构建。

## 六、环境变量清单（完整）

**这是部署最容易出错的地方。** 少配一个，可能整个功能不可用，而现象往往只是"登录失败"。

### 6.1 应用

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SERVER_PORT` | `8080` | 容器内监听端口（云托管里要和"服务端口"配置一致） |
| `SPRING_PROFILES_ACTIVE` | `dev` | **生产必须设成 `prod`** |
| `SPRINGDOC_ENABLED` | prod 下默认关 | 演示环境可开，生产建议关（会暴露全部接口结构） |

### 6.2 数据库

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DB_HOST` | `localhost` | 容器里要写服务名（如 `mysql`），**不能写 localhost** |
| `DB_PORT` | `3306` | |
| `DB_NAME` | `nqx` | |
| `DB_USERNAME` | `root` | 生产建议建专用账号，别用 root |
| `DB_PASSWORD` | `123456` | **必须改** |
| `DB_USE_SSL` | prod 下 `true` | 云托管 MySQL 若不支持 SSL，设成 `false` |

### 6.3 Redis

| 变量 | 默认值 | 说明 |
|---|---|---|
| `REDIS_HOST` | `localhost` | 同样要写服务名 |
| `REDIS_PORT` | `6379` | |
| `REDIS_PASSWORD` | `123456` | **必须改** |
| `REDIS_DATABASE` | `0` | 多个项目共用一套 Redis 时，用不同库号隔离 |

### 6.4 微信（⚠️ 最容易被漏掉）

| 变量 | 说明 |
|---|---|
| `WX_APP_ID` | 小程序 AppID |
| `WX_APP_SECRET` | 小程序密钥 |
| `WX_ORDER_TEMPLATE_ID` | 订单通知模板 ID（可选） |

> **⚠️ 为什么这几个不能漏**：
> `WeChatApiClient` 有一条设计——**生产环境下如果 `mock-enabled=false` 且 AppID/AppSecret 为空，它会直接拒绝所有登录**（而不是放行）。
>
> 这个设计本身是对的（忘配参数就该登不进去，免得人人可登录），但后果是：
> **变量漏配 → 整个小程序完全无法登录 → 而现象只是"登录失败"，不看日志根本想不到是环境变量问题。**

### 6.5 初始化管理员

| 变量 | 默认值 | 说明 |
|---|---|---|
| `INIT_ADMIN_USERNAME` | `admin` | 首次启动时创建 |
| `INIT_ADMIN_PASSWORD` | `Admin@123` | **必须改**；首次登录后立刻改密码 |

> 这两个只在 `sys_user` 表为空时生效，之后改环境变量不会再覆盖密码。

## 七、数据库与迁移

### 7.1 ⚠️ 两套数据库的数据不互通

| 方式 | 数据库在哪 | 数据 |
|---|---|---|
| 本地开发 | 本机 MySQL 3306 | 各有各的 |
| Docker | 容器 MySQL（宿主机映射端口） | **全新的库** |
| 云托管 | 平台托管 MySQL | **全新的库** |

**换一种跑法，业务数据不会跟过去。** 这是最常见"我的数据怎么没了"的原因。

### 7.2 表结构由 Flyway 自动管理

**不需要手动导 SQL。** 应用启动时会自动执行 `nqx-web/src/main/resources/db/migration/` 下的迁移脚本：

```
V1__init_schema.sql          建表
V2__init_data.sql            初始化数据（商品/分类/题库/FAQ/公告/管理员/权限）
V3 ~ V12                     历次结构修正
V13__fix_logical_delete_unique_key.sql   逻辑删除与唯一索引的修复
```

- 执行记录在 `flyway_schema_history` 表
- **只增不改**：已经执行过的脚本不要修改内容（校验会失败）
- 新增变更就加 `V14__xxx.sql`

### 7.3 初始化数据 vs 业务数据

| 类型 | 内容 | 上线后 |
|---|---|---|
| **初始化数据** | 商品、分类、回收品类、题库、FAQ、小贴士、公告、站点配置、管理员、角色、权限 | **保留**（系统运转的前提） |
| **业务数据** | 用户、地址、购物车、订单、积分、评价、维修、答题记录、日志 | **从 0 开始** |

**真实的系统初始化后，所有业务指标都应该是 0，数字只能由真实操作累积出来。**

## 八、数据重置（⚠️ 危险操作）

> **先读这一段再动手。**
>
> 这个脚本会 `DELETE FROM app_user` —— **删除用户账号**。账号一删，它名下的订单、地址、
> 积分流水、评价就全部失去归属，**不可恢复**。
>
> 曾经真实出过一次事故：把它当成"清一下测试数据"随手执行，结果把用户的真实使用记录
> 连账号一起删光，而当时没有任何备份。用户的原话是「正常软件的登录历史不可能消失」——
> **这句话是对的**。
>
> 事后排查确认：**登录逻辑本身没问题**。同一个 openid 重复登录会命中同一个用户，
> 订单、积分、地址完整保留（已实测：第 1 次登录 → 下单 → 第 2 次登录仍是同一 userId
> 且订单还在）。问题完全出在"被误用的清库脚本"。

### 8.1 现在它需要口令才能执行

脚本里加了一道强制确认：

```powershell
# 直接跑 → 报错退出，一条数据都不删：
Get-Content scripts\reset-business-data.sql -Raw |
    & 'D:\mysql\install\bin\mysql.exe' -uroot -p123456 --default-character-set=utf8mb4

# 输出：
#   ERROR 1644 (45000): 已拒绝执行：本脚本会删除全部用户账号与其历史记录（不可恢复）。
```

要真正执行，必须**先备份**，再取消脚本里这一行的注释：

```sql
-- SET @nqx_confirm_wipe := 'WIPE-ALL-DEMO-DATA';
```

### 8.2 正确顺序

```powershell
# 第 1 步：备份（必须）
.\scripts\backup-database.ps1

# 第 2 步：确认备份产物非空、含关键表（脚本会自己打印校验结果）

# 第 3 步：取消脚本里 SET @nqx_confirm_wipe 的注释，然后执行
Get-Content scripts\reset-business-data.sql -Raw |
    & 'D:\mysql\install\bin\mysql.exe' -uroot -p123456 --default-character-set=utf8mb4

# 第 4 步：清 Redis（Sa-Token 会话缓存在里面，不清会出现"库里没这个角色但旧会话仍按它鉴权"）
& 'E:\redis\Redis\redis-cli.exe' -a 123456 --no-auth-warning FLUSHDB
```

### 8.3 它到底删什么、留什么

| 删除 | 保留 |
|---|---|
| 用户账号、地址、购物车 | 商品、分类、回收品类 |
| 订单、订单明细、流转日志 | 题库、FAQ、小贴士、公告 |
| 积分账户、积分流水 | 站点配置 |
| 评价、维修申请、答题记录 | 管理员、角色、权限 |
| 操作日志、登录日志 | |
| 测试期间新建的管理员/角色/权限节点 | |
| 测试造的垃圾商品与题目 | |

**商品库存恢复初始值、销量归零**是有意的：库存是**初始资产**（配置），销量是**经营结果**（没有订单就不该有销量）。若销量显示"已售 156"而订单表是空的，报表之间就自相矛盾。

### 8.4 如果你只是想清掉自己测试的几行

**不要用这个脚本。** 按 id 或昵称精确删除对应数据即可 —— 删除范围越小越安全：

```sql
-- 只删某个测试用户及其数据（把 '测试昵称' 换成实际昵称）
SET @uid := (SELECT id FROM nqx.app_user WHERE nickname = '测试昵称');
DELETE FROM nqx.order_flow  WHERE order_id IN (SELECT id FROM nqx.biz_order WHERE user_id = @uid);
DELETE FROM nqx.order_item  WHERE order_id IN (SELECT id FROM nqx.biz_order WHERE user_id = @uid);
DELETE FROM nqx.biz_order   WHERE user_id = @uid;
DELETE FROM nqx.points_record  WHERE user_id = @uid;
DELETE FROM nqx.points_account WHERE user_id = @uid;
DELETE FROM nqx.user_address   WHERE user_id = @uid;
DELETE FROM nqx.app_user_role  WHERE user_id = @uid;
DELETE FROM nqx.app_user       WHERE id = @uid;
```

> **一条通用原则**：凡是"清空全部"的操作，先问一句"备份了吗"。删除范围越精确，越不需要备份。

## 九、备份与恢复

> **为什么这一节要单独强调**：因为第 8 节那个清库脚本存在过误用事故。
> 现在的规矩是 —— **任何清空/重置之前先跑备份**。

### 9.1 备份数据库（用脚本，别手打命令）

```powershell
.\scripts\backup-database.ps1
```

它会：
1. 用 `mysqldump --single-transaction` 导出（不锁表，线上可跑）
2. **自己校验**：文件大小、结尾的 `Dump completed` 标记、关键表建表语句是否都在
3. 打印恢复命令
4. 自动清理超过 30 天的旧备份（`-KeepDays 0` 可关闭）

**为什么要用脚本而不是手敲命令**：手敲的 `mysqldump ... > file.sql` 有两个坑 ——
① stderr 里的密码提示会被 PowerShell 当成错误终止脚本（脚本里已处理）；
② 导出可能中途失败却留下一个非空但残缺的文件，而你不知道。
脚本会主动检查这两点。

### 9.2 恢复

```powershell
& 'D:\mysql\install\bin\mysql.exe' -uroot -p123456 `
    --default-character-set=utf8mb4 nqx < backup\nqx_20260101_1200.sql
```

（PowerShell 不认 `<` 重定向，实际执行时用 `cmd /c "… < file.sql"`。）

### 9.3 验证备份真的能恢复

**这是本节最重要的一条：没验证过的备份等于没有备份。**

做法：恢复到一个**临时库**，对比行数，确认无误后再删掉临时库。

```powershell
# 1. 建临时库
& 'D:\mysql\install\bin\mysql.exe' -uroot -p123456 -e "CREATE DATABASE nqx_restore_test DEFAULT CHARACTER SET utf8mb4;"

# 2. 导入
cmd /c '"D:\mysql\install\bin\mysql.exe" -uroot -p123456 --default-character-set=utf8mb4 nqx_restore_test < "backup\nqx_xxx.sql"'

# 3. 对比关键表行数（应与原库一致）
& 'D:\mysql\install\bin\mysql.exe' -uroot -p123456 -e "SELECT (SELECT COUNT(*) FROM nqx.app_user) AS 原, (SELECT COUNT(*) FROM nqx_restore_test.app_user) AS 恢复;"

# 4. 删掉临时库
& 'D:\mysql\install\bin\mysql.exe' -uroot -p123456 -e "DROP DATABASE nqx_restore_test;"
```

> 本项目已实测过一次：恢复后 `用户 1 / 订单 1 / 商品 11 / 权限 65` 与原库完全一致。

### 9.4 还要备份什么

| 内容 | 位置 |
|---|---|
| 上传的文件（商品图等） | `uploads/` 目录 |
| `.env` 配置文件 | 项目根目录（**含密码，不要进 Git**） |
| 日志 | `app.log`（排查问题用，可定期归档） |

## 十、端口规划（多项目共存）

一台机器跑多个项目时，最容易撞的就是端口。**给每个项目划一段专属区间**：

| 项目 | MySQL | Redis | 应用 | 前端 |
|---|---|---|---|---|
| wenshu（其它项目） | — (PG 5432) | 16379 | — | — |
| **nqx（本项目）** | **13306** | **13379** | **8080** | 5173（dev）/ 8888 |

### 查端口占用

```powershell
netstat -ano | Select-String "LISTENING"
```

看某一端口被谁占：

```powershell
netstat -ano | Select-String ":3306\s"
Get-Process -Id <PID>
```

### ⚠️ Windows 上两个常见"端口被莫名占用"

| 端口 | 常见占用者 | 怎么办 |
|---|---|---|
| **80** | **IIS**（`W3SVC` 服务，装 VS/SQL Server 会顺带装上） | `Stop-Service W3SVC`，或让 Nginx 改听 8888 |
| 443 | 一般空闲 | 若被占用，多半是 IIS 或其它 Web 服务 |

**查 IIS 有没有在跑**：

```powershell
Get-Service W3SVC
# 管理员 PowerShell：
& "$env:windir\system32\inetsrv\appcmd.exe" list sites
```

只有一个 Default Web Site、且指向空目录，说明没在用，可以安全停掉或禁用。

## 十一、故障排查

### 11.1 启动失败

```powershell
# 看日志
Get-Content app.log -Tail 80
```

| 现象 | 原因 | 解决 |
|---|---|---|
| `Failed to connect to database` | 数据库没起 / 地址错 | 检查 MySQL 是否在跑；容器里 `DB_HOST` 要写服务名不是 `localhost` |
| `Migration ... failed` | Flyway 脚本出错 | 看错误里是哪一句；**先修脚本再重跑**，别改已执行的脚本 |
| `Duplicate entry` | 唯一索引冲突 | 见 `docs/06-踩坑记录.md` 第 30 条 |
| `port already in use` | 端口被占 | 换端口或停掉占用进程 |
| `ClassNotFoundException` / `NoSuchMethodError` | 依赖版本冲突 | 见 `docs/04-依赖版本锁定.md`；这类错误**编译期不报，运行期才炸** |

### 11.2 登录相关

| 现象 | 排查 |
|---|---|
| 小程序完全无法登录 | 检查 `WX_APP_ID` / `WX_APP_SECRET` 是否配了；`SPRING_PROFILES_ACTIVE` 对不对 |
| 登录成功但一操作就 401 | Redis 里的会话丢了；检查 Redis 是否在跑、`REDIS_PASSWORD` 对不对 |
| 改了权限但没生效 | 正常情况下改了立刻失效缓存；若没生效，看 `StpInterfaceImpl` 的日志 |
| **用 SQL / 迁移脚本改了权限，后台仍报 403** | Sa-Token 把权限码缓存在 **Account-Session**（按登录用户 id 缓存，跨 token 共享，且持久化在 Redis）。用 SQL 直接改 `sys_role_permission` **不会**触发缓存失效，必须手动清掉：<br>`redis-cli -a 密码 DEL 'Authorization:admin:session:<管理员id>'`<br>删完重新登录即可。**不要 FLUSHDB** —— 那会把所有小程序用户的登录态一起清掉。 |
| 管理员密码忘了 | 进 MySQL 改 `sys_user.password`（BCrypt 密文），或重置 `sys_user` 表后重启让初始化重跑 |

### 11.3 数据看不到

| 现象 | 疑似原因 |
|---|---|
| 列表一直空 | ① 换了运行方式（不同库）② 逻辑删除把数据标记了 ③ 权限过滤 |
| 某个字段全是空白 | 前后端字段名不一致（见 `docs/06` 第 26/27 条） |
| 库存/销量对不上 | 缓存没失效（`ProductService.deductStock` 已处理） |

- [ ] `SPRING_PROFILES_ACTIVE=prod`
